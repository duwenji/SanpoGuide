# 散策ガイド (SanpoGuide)

散策の友として、一緒に歩きながら周辺のスポットを案内し、状況に合わせて話しかける Android アプリ（MVP）。

## 機能

- **地図＋一覧**: 現在地周辺（半径 600m）の史跡・寺社・公園・博物館などを OpenStreetMap から取得し、国土地理院の地図上に表示
- **散策に役立つ施設**: トイレ・水飲み場・自動販売機・休憩所（屋根のある場所）・ベンチを地図に色分けして表示し、種類ごとに最寄りの距離を地図の上に並べる（タップで地図がその場所へ移動）。ベンチと自動販売機は半径 250m 以内だけ。私有・立入禁止（`access=private|no`）のものと、切符・駐車券・たばこなどの自動販売機は除く（店舗の利用者向けトイレは表示する）。散策中は、状況に合うときだけ音声でも案内する（下記）
- **AI 解説**: スポットをタップすると、AI がガイド風の解説を生成
- **音声読み上げ**: 解説を日本語 TTS で読み上げ
- **散策モード（散歩の友）**: バックグラウンドで散歩を追跡し、状況に合わせて話しかける（下記）
- **散歩の記録**: 散歩ごとの日時・距離・時間・経路・案内したスポットと話した内容を端末内に保存し、記録画面（右上の時計アイコン）で振り返れる
- **設定**: 設定画面（右上の歯車）で AI サービス・API キー・モデル・話しかけの頻度・案内のしきい値を選ぶ

## 散歩の友（話しかけ）

散策モードでは、次の場面で音声で話しかける。話しかけた内容はメイン画面上部のカードに表示される（タップで過去の発言を展開）。

| 場面 | 内容 |
|---|---|
| 散歩の開始 | 時間帯・天気・前回の散歩からの日数に触れたあいさつ |
| スポットの 60m 以内に来た（初めて） | スポットの解説（通知も出す） |
| スポットの 60m 以内に来た（過去の散歩で訪問済み） | 何回目か・前回話した内容を踏まえた短い一言。同じ解説は繰り返さない |
| 一定の距離・時間を歩いた | 距離・時間・天気・時間帯に合わせた一言 |
| 同じ場所に 4 分以上とどまった | 休憩に合わせた一言 |
| 1 時間以内に天気が崩れる予報（雷雨・強い雨・雨や雪の降り始め） | 何分後に崩れそうか（10 分未満なら「まもなく」）と備え（雷なら建物へ、雨なら傘・雨宿り）の一言。すでにその天気のときは話さない。同じ種類は 1 時間あけ、雷雨の予告は雨の予告も兼ねる。話しかけの頻度に関係なく、スポット案内より優先して話す |
| 日の入りの 30〜5 分前 | 日の入りが近いことと帰り道を意識する一言（1 回の散歩につき 1 度。話しかけの頻度に関係なく話す） |
| 状況に合った施設が近くにある | 施設の種類・距離・方向（前方・右手・左手・後ろ。歩いているときだけ）を伝える一言（下表） |
| 散歩の終了 | 距離・時間・案内したスポットの振り返り |

話しかけるときは、日時・季節・天気・今回の散歩（経過時間・距離・案内した場所）・過去の散歩（回数・前回の日時・この 7 日間・今日何回目か）・直近の発言を AI に渡し、繰り返しを避ける。同じスポットは 1 回の散歩につき 1 度だけ話題にする。

「60m 以内」は、公園や境内など広さのあるスポットでは中心ではなく境界からの距離で判定する（敷地に入った時点、または境界の 60m 手前で案内する）。

再訪したスポットでの一言には天気を渡さない（渡すと毎回天気の話になるため）。訪問回数は「通算◯回目（今日だけで◯回目）」の形で渡す。

過去の訪問は、スポットの ID が一致するか、同じ名前で 200m 以内（広さのあるスポットは境界から 200m 以内）にあれば同じ場所とみなす。OpenStreetMap では同じ場所が点と範囲の両方で登録されていることが多く、検索した地点によって返る方が変わるため、ID だけでは再訪を見逃す。

施設の案内は、次の条件のときだけ行う（上から優先）。同じ施設は 1 回の散歩につき 1 度だけ、同じ条件の案内は表の間隔をあける。雑談と同じく、話しかけの頻度の「雑談の間隔」も守る。

天気の急変・日の入り・施設の案内で使う時間・距離・気温・雨量（この節の数値）は、設定画面の「案内のしきい値」で変えられる。記載の値は既定値。既定値から変えた項目だけを保存するので、アプリの既定値が変わった場合、変えていない項目には新しい既定値が使われる。一覧と範囲は `settings/Threshold.kt` にある。

| 条件 | 施設 | 距離 | 間隔 |
|---|---|---|---|
| 雨・雪が降っている | 休憩所 | 150m 以内 | 20 分 |
| 歩き始めて 20 分以上 | トイレ | 100m 以内 | 45 分 |
| 歩き始めて 15 分以上で、気温 25℃ 以上 | 水飲み場・自動販売機 | 80m 以内 | 30 分 |
| 歩き始めて 40 分以上 | ベンチ・休憩所 | 60m 以内 | 40 分 |

話しかけの頻度は設定で選べる。

| 頻度 | スポット案内の間隔 | 雑談の間隔 | 距離・時間の区切り | 休憩の声かけ |
|---|---|---|---|---|
| 控えめ | 5 分以上 | 6 分以上 | 2km または 30 分 | しない |
| ふつう（既定） | 2 分以上 | 3 分以上 | 1km または 15 分 | する |
| おしゃべり | 1 分以上 | 2 分以上 | 500m または 8 分 | する |

近くに複数のスポットがある場合は、Wikipedia の記事があるスポットや、寺社・博物館などの主要なスポットを優先する。読み上げ中は次の発言を始めない。同じ場所に 2 分以上とどまっている間は、新しいスポットの案内をしない（スポットが密集した場所で次々と紹介し続けないため）。

API キーが未設定、または AI の呼び出しに失敗した場合は、定型文（「〇〇、2回目ですね。」など）で話しかける。

プロンプトと定型文の文言は [docs/prompts.md](docs/prompts.md) にまとめたファイルで管理している。

## 対応 AI サービス

| サービス | 接続方式 | 既定モデル |
|---|---|---|
| Claude (Anthropic) | 公式 Java SDK | `claude-opus-5`（`claude-sonnet-5` / `claude-haiku-4-5` も選択可） |
| DeepSeek | OpenAI 互換 API | `deepseek-chat` |
| OpenAI | OpenAI 互換 API | `gpt-5-mini` |
| Gemini (Google) | OpenAI 互換エンドポイント | `gemini-2.5-flash` |
| カスタム | OpenAI 互換 API（接続先 URL を指定） | 任意 |

Claude 以外のモデル名は自由に書き換えられる。カスタムは OpenRouter・Groq・ローカル LLM（Ollama など）のように、`/chat/completions` を持つサービスなら使える。

API キーが未設定の場合は、地図データのタグから作る簡易解説で動作する。

## セットアップ

必要な環境: JDK 17、Android SDK（compileSdk 35）。対応端末は Android 8.0（API 26）以上。

```sh
./gradlew installDebug
```

アプリの設定画面で API キーを入力し、「接続テスト」で確認してから保存する。

エミュレータでは、Extended controls → Location で現在地を指定する（例: 鎌倉駅周辺）。

### リリース版のビルド

署名用のキーストアを作り、`keystore.properties.example` を `keystore.properties` にコピーしてパスワードを記入する。どちらも Git には入れない（`.gitignore` 済み）。キーストアとパスワードを失うと、同じアプリとして更新できなくなるので、別の場所にも保管する。

```sh
keytool -genkeypair -v -keystore release.jks -alias sanpoguide -keyalg RSA -keysize 2048 -validity 10000
./gradlew assembleRelease
```

出力: `app/build/outputs/apk/release/app-release.apk`。`keystore.properties` がない場合は署名なしの `app-release-unsigned.apk` になる。

### アプリが求める権限

| 権限 | 用途 |
|---|---|
| 位置情報 | 周辺スポットの検索、散策モードでの接近検知・距離の記録 |
| 通知（Android 13 以上） | 散策モード中の常駐通知、スポット案内の通知 |

散策モードは位置情報を使うフォアグラウンドサービスとして動く。「散策を終える」ボタンか、通知の「終了」で止まる。

## 構成

| パッケージ | 役割 |
|---|---|
| `data` | Overpass API によるスポット検索（`OverpassClient`）、現在地・スポットの共有状態（`SpotRepository`） |
| `guide` | AI サービスの抽象（`LlmClient` / `Provider`）、Claude（`ClaudeClient`）と OpenAI 互換（`OpenAiCompatibleClient`）の実装、スポット解説のプロンプト変数（`GuidePrompt`）、キャッシュ（`GuideRepository`）、TTS（`Speaker`） |
| `prompt` | プロンプトファイルの読み込みと組み立て（`PromptTemplates`）、ファイルのパス一覧（`Prompts`） |
| `companion` | 散歩の友の発話（状況を集めてプロンプト変数にする。`WalkCompanion`）、進行中の散歩の状態（`WalkSession`）、画面向けの発言・散歩状況（`CompanionFeed`）、天気の取得（`WeatherClient`） |
| `history` | 散歩の記録の保存（`HistoryStore`） |
| `settings` | 設定の保存（`SettingsRepository`）、API キーの暗号化（`KeyCipher`）、話しかけの頻度（`TalkLevel`） |
| `walk` | 散策モードのフォアグラウンドサービス。位置の追跡と「いつ何を話すか」の判断（`WalkService`） |
| `ui` | Compose の画面（メイン・記録・設定）、発言カード、地図、ViewModel |

AI に送るプロンプトと定型文は、コードではなく `app/src/main/assets/prompts/` のファイルにある。一覧・使う場面・書き方・変数は [docs/prompts.md](docs/prompts.md) を参照。

AI サービスを追加する場合、OpenAI 互換なら `Provider` に1行追加するだけでよい。独自 API の場合は `LlmClient` を実装し、`GuideRepository.createClient` に分岐を足す。

## API キーの扱い

- 利用者が自分の API キーを入力する方式。キーは APK に含まれない。
- キーは Android Keystore の AES 鍵で暗号化して SharedPreferences に保存する（`allowBackup=false`）。
- キーは選択した AI サービスへの通信にだけ使い、ログには出力しない。

## 散歩の記録の扱い

- 記録はアプリ専用の領域（`walk_history.json`）にだけ保存し、外部には送らない（`allowBackup=false`）。
- AI に話しかけ文を作らせるときは、日時・天気・距離・訪問回数・スポット名・前回話した内容を送る。**緯度経度や経路は AI に送らない**（天気の取得には現在地の緯度経度を Open-Meteo に送る）。
- 保存する散歩は最新 500 件まで。記録画面のゴミ箱アイコンですべて削除できる。
- 1 分未満で、スポットの案内もなかった散歩は保存しない。

## 外部サービス

- **スポット検索**: OpenStreetMap の Overpass API（公開サーバー）。散策に役立つ施設も同じリクエストで取得する（種類ごとに最大 40 件）。混雑で失敗した場合は、次の順に予備サーバーへ切り替える: `overpass-api.de` → `overpass.private.coffee` → `maps.mail.ru`。散策モードでは、前回の検索地点から 300m 以上移動したときに再検索する。
- **地図**: 国土地理院の標準地図タイル（出典表示あり）。OpenStreetMap の公式タイルサーバーはアプリからの利用に制限があるため使っていない。
- **天気**: Open-Meteo（無料・API キー不要）。散歩の開始時と 15 分ごとに、現在の天気・この先 2 時間の 15 分ごとの予報・当日の日の入り時刻を取得する。データは CC BY 4.0 のため、設定画面に出典を表示している。

公開サーバーには利用ポリシーがある。利用者が増える場合は自前のサーバーや商用のサービスを検討する。

## 既知の課題

- **スポット検索のタイムアウト**: 公開の Overpass サーバーが混雑していると、3つのサーバーすべてで失敗することがある（テストで発生、再検索で成功）。現状は 1 サーバーあたり最大 40 秒待つため、失敗までに時間がかかる。
- **解説の正確さ**: プロンプトで創作を禁じているが、モデルの知識が古い・不正確な場合がある（例: DeepSeek による若宮大路の解説で、2016 年に作り直された段葛を「大正時代に整備」と説明）。モデルによって精度に差がある。
- **解説の長さ・距離感**: 指示（200〜300 字）より長めになる（DeepSeek では鶴岡八幡宮で約 500 字）、離れたスポットを「今いらっしゃる辺り」と表現する、などのずれがある。
- **「訪問」の判定**: スポットの 60m 以内を通過しただけでも訪問として記録する（実際に立ち寄ったかは区別しない）。
- **話しかけの内容（DeepSeek で確認）**: 状況に合った一言になるが、見ていないもの（「霧雨の鐘の音」など）を想像で話すことがある。直前の発言で天気に触れていると、再訪の一言でも天気の話が混ざることがある。
