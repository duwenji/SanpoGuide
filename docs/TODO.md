## 雰囲気

時間帯・季節・天気・場所の種類から「今の雰囲気」を決め、画面・音・話し方をそろえて変える。第 1 版は実装済み（README「雰囲気」）。

- [x] 雰囲気を表すモデル（`mood/Mood.kt`。時間帯・季節は `WalkCompanion` から切り出して共通にした）
- [x] 画面の配色・フォントの切り替え（`ui/MoodTheme.kt`）と、散策中のカード上部の絵（`ui/MoodScene.kt`）
- [x] 話しかけのトーンに反映する（`companion/situation` の変数 `mood`、指示は `companion/system`）
- [x] 設定でオン・オフ（既定はオン）
- [ ] 実際に歩いて、場所の種類の推定が合っているか確かめる（とくに「史跡」: 鎌倉では石碑などの `historic` が多く、寺社の近くでも史跡と判定されやすかった）
- [ ] AI のトーンの変わり方を確かめる（エミュレータでは API キーなしの定型文でしか確認していない）
- [ ] 明朝体（寺社・史跡の近く）がアプリ全体（設定画面を含む）にかかる。解説とカードだけに絞るか検討
- [ ] 海岸線（`natural=coastline`）は、形が大きく検索が重くなるので入れていない。名前のある砂浜（`natural=beach`）と水面（`natural=water`）だけで水辺を判定している

決めたこと（2026-09-29）:
- 場所の種類は周辺スポットのカテゴリから推定する（敷地の中にいればその種類、なければ 150m 以内の多数決。地図の土地利用は使わない）
- 場所は 3 分続いたら切り替える。空模様は天気の取得（15 分ごと）に合わせて変わる。時刻は 1 分ごとに見直す
- 天気は `CompanionFeed.weather` に載せて画面と共有する。散策モード外は空模様なし

## 背景画像

雰囲気や近くのスポットに合った画像を表示する。第 1 版は実装済み。

- [x] 画像の出どころ: 雰囲気の絵はアプリで描画する（同梱の画像ファイルではない。ライセンス表示・通信が不要で、時間帯・天気・場所のどの組み合わせにも絵がある）。スポットの写真は Wikimedia Commons
- [x] 地図との共存: 地図には重ねない。雰囲気の絵は散策中の発言カードの上部（高さ 72dp）だけ、写真は解説の画面（スポットをタップしたとき）だけに出す
- [x] 近くのスポットの写真を表示する（タグの `wikimedia_commons`・`image`、なければ `wikidata` → P18。`data/SpotPhotos.kt`）
- [x] 通信量を抑える（既定は従量制でない回線のときだけ取得、幅 800px の縮小版、ディスクキャッシュ 30MB・メモリ 8 枚）
- [ ] 散策中に案内したスポットの写真を、カードの絵の代わりに出すかどうか（画面を見させない方針とのかね合い）
- [ ] 描画の絵の見た目の調整（今は図形の組み合わせで素朴。イラストを描き起こして同梱するかは、見た目への要望次第）

決めたこと（2026-09-29）:
- 優先度: 散策モードで画面を開いたときの演出程度にとどめる（★ → ☆）
- ライセンス表示: 写真のすぐ下に「写真: 作者 / ライセンス / Wikimedia Commons」を出し、タップで Commons のファイルのページを開く。設定画面の出典にも Wikimedia Commons を加えた
- 画像生成 AI は使わない（費用・生成時間・品質のばらつき）

## 背景音

雰囲気に合わせた環境音を流す。第 1 版は実装済み（README「背景音」）。

- [x] 読み上げ（`Speaker`）でオーディオフォーカス（`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK`）を取る（エミュレータで要求・解放が対になっていることを確認）
- [x] 音源: 同梱せず端末で合成する（雨音・波・風・鳥の声・虫の音・遠くの鐘の 6 種類。`sound/Voices.kt`）
- [x] 読み上げ中は背景音の音量を下げる（`Speaker.speaking` を見て 2 割に）
- [x] 他のアプリの音楽再生との共存（再生中の音声のうち、自分以外のメディア・ゲームがあれば流さない。`isMusicActive` は自分の音でも true になるため、`getActivePlaybackConfigurations` の用途・種類で見分ける）
- [x] 音量・オン・オフの設定（既定はオフ・音量 40%）
- [x] バックグラウンド（散策モードのフォアグラウンドサービス）での再生（エミュレータで再生状態を確認）
- [ ] 実機のイヤホン（有線・Bluetooth）で、音質・音量・切り替えのフェード・イヤホンを外したときの停止を確かめる
- [ ] 他のアプリで音楽を再生したときに止まることを実機で確かめる（エミュレータでは未確認）
- [ ] 合成の音が安っぽければ、ライセンスの明確な録音素材（OGG のループ）に置き換える。`Soundscape` と選び方はそのまま使える
- [ ] 電池の消費を計測する（22,050Hz・モノラルの合成を 50ms ごと）

決めたこと（2026-09-29）:
- イヤホンがないときは流さない（既定）。設定でスピーカーからも流せる
- 安全面: 既定はオフ、音量は控えめ、設定画面に「車や自転車の近づく音が聞こえる音量に」と表示。雷雨のときも雷鳴は合成しない。交通量による自動の抑制はしない（交通量を知る手段がないため）

場所に紐づく外部のコンテンツ（観光協会の音声ガイド、店舗の紹介、イベント告知、広告など）を、その場所に近づいたときに再生・表示する。

- [ ] コンテンツの形式（音声・動画・画像・テキスト・リンク）
- [ ] 配信の仕組み（コンテンツと位置・期間・対象範囲を登録するサーバーが必要）
- [ ] 提供者が登録する方法（管理画面、または提携先からのデータ取り込み）
- [ ] 広告であることの明示と、ガイドの解説と混同させない表示
- [ ] 表示頻度の上限（散策の邪魔にならないように）
- [ ] 設定で広告をオフにできるか、有料プランとの関係

決めること:
- 収益化の方針（広告、有料プラン、提携）
- 広告配信のために位置情報を外部に送るかどうか。送る場合は同意の取得とプライバシーポリシーの更新が必要（現在は「緯度経度や経路は AI に送らない」方針）
- 既存の広告 SDK を使うか、自前で配信するか
- 第三者のコンテンツの審査（不適切な内容・虚偽の防止）

## 位置に紐づく秘密メッセージ

特定の場所に来たときだけ読める・聞けるメッセージ。ジオキャッシュのように、場所に「置いて」おき、その場所に来た人が見つける。

利用場面の例:
- 自分宛て: 「1 年後にまたここに来たら読む」メッセージ
- 家族・友人宛て: 特定の人だけが開けるメッセージ
- 公開: その場所を訪れた人なら誰でも見つけられる（宝探し、イベント）
- 第三者の媒体（上記）と組み合わせた、店舗やイベントの隠しコンテンツ

- [ ] メッセージを置く（現在地、または地図上の地点を指定）
- [ ] 開ける条件（半径◯m 以内、日時・期間、特定の相手、合言葉）
- [ ] 近くに来たら通知し、話しかけで知らせる
- [ ] 形式（テキスト・音声・写真）
- [ ] 自分宛てだけなら端末内で完結、他人宛てならサーバーと本人確認が必要

自分宛てだけならサーバーなしで作れる（`HistoryStore` と同じく端末内に保存）。先にここだけ切り出して着手できる。

他人宛て・グループ・公開のサーバー API は [secret-messages-api.md](secret-messages-api.md)（API-001、2026-09-29 承認）で決めた。接続先は URL で設定し、API に準拠していればサーバーの実装方法・置き場所は問わない。第 1 版は個人宛て・グループ・受信フィルター・メッセージの管理。

## 共通の検討事項

- **サーバーの要否**: 第三者の媒体・他人宛ての秘密メッセージはサーバーが必要。現在のアプリはサーバーを持たず、端末と公開 API だけで動いている。項目ごとにばらばらに決めず、1 つの判断（ADR）としてまとめて決める。
  - 秘密メッセージ（第三者の媒体の配信を含む）は、[secret-messages-api.md](secret-messages-api.md) の API に準拠したサーバーを URL で指定する形に決めた（2026-09-29）。実装方法・置き場所は問わない
- **プライバシー**: 位置情報を外部に送る範囲が広がる。README の「散歩の記録の扱い」を更新し、同意を取る。
- **安全**: 歩きながら画面を見させない。音声中心の案内を基本にする。
- **電池・通信量**: 画像・音声の取得と再生が増えるため、散策モードでの消費を計測する。天気の取得は 15 分ごとに増やした（予報の取得のため）。
- **公開サーバーの負荷**: Overpass・Open-Meteo は公開サーバーを使っている。取得する項目と頻度が増えてきたので、利用者が増える前に利用ポリシーを確認し、自前のサーバーや商用のサービスを検討する。
